# Pluggy rules (read before changing Pluggy code)
- Pluggy (`src/lib/pluggy/rules.ts`, `src/server/pluggy/*`): two-UUID allowlist AND `owner`, Sandbox-only, writes only `pluggy_*` (candidate SQL tested by `scripts/test-pluggy-sql.sh`); the webhook only enqueues and `/api/public/pluggy/worker` processes via claim/lease RPCs with limited retries, because test data must never reach real finances and acks must be durable and idempotent.
- Pluggy → Gastos/Receitas import is planned by the pure `src/lib/pluggy/import-plan.ts` and written only through the candidate transactional RPCs in `docs/migrations-candidate/pluggy-import-gi.sql` (`pluggy_import_apply`/`pluggy_import_revert`, service_role only, tracked in `pluggy_import_entries`), behind `PLUGGY_IMPORT_RELEASE_AUTHORIZED` in `src/server/pluggy/pluggy-import.server.ts`, because imports must be all-or-nothing, idempotent, and reversible without touching other origins.
